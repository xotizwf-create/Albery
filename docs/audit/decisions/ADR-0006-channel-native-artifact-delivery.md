# ADR-0006: Deliver generated artifacts through the owning channel

- Status: accepted
- Date: 2026-08-12
- Owners: Albery owner
- Supersedes: none

## Context

Generated documents currently reach employees through public HMAC+TTL download URLs. The URL is
unguessable but transferable to anybody who receives it, expires after 30 minutes, and the exact
generated bytes are not retained in the durable attachment store. A final-channel adapter already
owns recipient identity and sender identity, so it is the correct boundary for file delivery.

## Decision

- Bitrix agents upload generated files directly into the same bot dialogue through the official
  bot file API; employee-facing text must not contain an Albery export URL.
- Employee Telegram agents send generated files through `sendDocument` from the same profile bot.
- The durable channel outbox stores an unguessable local attachment capability, never raw bytes or
  a signed public URL in its row.
- Generated bytes are retained in the existing restricted attachment store for the configured
  short retention period so retries and later edits preserve exact formatting.
- Public signed export URLs remain only as an internal model-to-adapter handoff and for explicitly
  non-chat consumers. The legacy `mcp.m4s.ru/zoom-export/` compatibility route is removed now that
  the owner confirms no old links remain.
- Unknown or invalid Albery artifact links fail closed: the channel sends an explicit delivery
  error rather than leaking a broken URL.

## Alternatives considered

- Longer public TTL: improves convenience but increases the bearer-link exposure window.
- Universal URL crawler: rejects authenticated Bitrix/Drive links, can mutate one-time URLs and
  leaks credentials into probes/logs.
- Store only extracted text: cannot reproduce the original layout and exact bytes after expiry.

## Consequences

- Recipients use native channel access instead of a transferable public URL.
- Bitrix and Telegram delivery code must understand durable artifact attachments and ambiguous
  provider outcomes.
- Exact generated files occupy restricted local storage until retention cleanup; size and age
  policies remain mandatory.
- A direct-channel live round trip is required before marking the implementation verified.

## Verification / revisit trigger

Verify exact bytes, filename, sender bot, recipient scope, retry behavior, invalid/expired handoff,
no visible `/zoom-export/` URL, file permissions, cleanup, and public MCP/default 404 behavior.
Revisit if artifacts move to object storage or if a channel supplies a stronger one-time delivery
primitive.
